Phase B · Query  —  answer a question (runs every time)

Retrieve the most relevant chunks, then let Claude answer using only those.

6

❓Question → hybrid retrieve → re-rank

The question is matched two ways at once — keyword (BM25) and semantic (Nebius embeddings + Pinecone) — fused into one candidate pool, then a cross-encoder re-ranker (FlashRank) keeps the most relevant top 4 chunks. Casting a wide net then re-ranking is more precise than either search alone.

▼
7

🤖Generate · CLAUDE

The retrieved chunks become the context for Claude. A strict prompt tells it to answer only from that context, cite the policies it used, and reply “not covered in the HR knowledge base” when the answer isn’t there.

8

✅Answer + sources

The user gets a concise answer with the source policy titles — or a safe decline. Because Claude is constrained to the context, it doesn’t invent policies that don’t exist.

grounded answercited sourcesno hallucinated policy
Why “answer-from-context-only” matters: a chatbot that confidently makes up an HR policy is worse than useless. The guardrail turns “I don’t have that” into a feature — the system declines instead of guessing.
Then · Stress test  —  15 questions, 4 difficulty types

Each question type probes a different strength or weakness of retrieval.

Direct factual × 6

One clear answer in one document. Retrieval should nail it.

“What is the 401(k) match?”

Ambiguous × 3

Underspecified wording — retrieval reflects the ambiguity instead of resolving it.

“What’s the deadline?”

Multi-document × 3

Answer needs chunks from two source docs — tests cross-document recall.

“New remote hire: setup + remote rules?”

Unanswerable × 3

Topic isn’t in the KB. Success = a clean decline, not a fabricated policy.

“What is the relocation policy?”

✅ Succeeds on specific factual & unanswerable questions  ·  ⚠️ Struggles with ambiguous & multi-document queries (the documented failure modes).

Findings & next steps

✅ Where it succeeds

Specific factual lookups return correct, cited answers. Unanswerable questions are declined rather than hallucinated — the most important safety behavior.

⚠️ Where it fails

Ambiguous queries have no subject to anchor on; multi-document answers under-retrieve the second document because top-k by similarity favors one cluster.

✅ Implemented — Hybrid + re-rank

BM25 keyword + dense vector fused, then cross-encoder re-ranked — this is what pulls exact-term chunks (like “401(k)”) into the final context that pure vector search missed.

🔧 Next — Metadata filtering & query decomposition

Filter by policy area for ambiguous queries; split multi-part questions into sub-queries so each aspect retrieves its own best chunk.
